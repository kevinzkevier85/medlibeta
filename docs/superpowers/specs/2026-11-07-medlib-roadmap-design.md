# MedLib roadmap — เชื่อถือได้ก่อน แล้วค่อยเพิ่มฟีเจอร์อ่านสอบ

วันที่: 2026-11-07 · ผู้ตัดสินใจ: Finn · สถานะ: รอตรวจ

## บริบท (จากการคุยกับผู้ใช้)
- ผู้ใช้: **เพื่อนทั้งรุ่น** → เฉลยต้องน่าเชื่อถือ เว็บต้องเสถียร
- ใช้หนัก **1–2 สัปดาห์ก่อนสอบ** → เน้นทำข้อสอบเก่าเยอะ ๆ และทบทวนข้อที่ผิด
- **สลับหลายเครื่อง** → ความคืบหน้าต้องตามไปทุกเครื่อง
- ลำดับ: แก้ให้เชื่อถือได้ก่อน → ฟีเจอร์อ่านสอบ → ความสะดวก
- Cloudflare Worker: Claude เขียนโค้ดและคู่มือ **kevinzkevier85 เป็นคนตั้ง** (บัญชี Cloudflare ฟรี)

## หลักที่ใช้ทุกขั้น
- 1 ขั้น = 1 branch `finn-…` = 1 PR ให้อีกคนตรวจและ merge (CLAUDE.md)
- กติกาข้อมูลอยู่ที่ `lib/validate.js` ที่เดียว · ทุก PR ออกเวอร์ชันใหม่ · `node tools/validate.cjs` และ `_test/quizcore.test.cjs` ต้องผ่าน · ลองในเบราว์เซอร์ทั้งคอมและมือถือ
- ข้อมูลส่วนตัวใช้ key/รหัสข้อเดิม (`id`) ทั้งหมด ไม่ทำให้คะแนนเก่าหาย

## ขั้น 1 — ข้อที่เฉลยยังไม่ยืนยัน (หน้าเว็บ)
**ปัญหา:** ~200 ข้อเป็น `draft` / `disputed` แสดงปนกับข้ออื่น ป้ายอยู่แค่ในกล่องคำอธิบาย และนับคะแนนเหมือนข้อปกติ
**ทำ**
- ป้ายเตือนบนหัวข้อของข้อ (ก่อนตอบ): "เฉลยยังไม่ยืนยัน" / "เฉลยต้นฉบับอาจคลาดเคลื่อน"
- **ไม่นับคะแนน:** `roundStats`, ความคืบหน้าบนการ์ด, จุดอ่อน ข้ามข้อเหล่านี้ (ยังทำและเห็นเฉลยได้)
- หน้าสรุปผลแยกแสดง "ข้อที่ไม่นับคะแนน (N)"
- การตั้งค่า "แสดงข้อสอบที่เฉลยยังไม่ยืนยัน" ยังอยู่ ค่าเริ่มต้นแสดง
**ไฟล์:** `lib/quizcore.js` (นับคะแนน), `quiz.js`, `styles.css` · เพิ่มเทสใน `_test/quizcore.test.cjs`

## ขั้น 2 — Worker ตัวเดียว: PDF + แจ้งเฉลย + sync
**มีอยู่แล้ว:** `worker/drive-proxy.js` ทำ PDF proxy (`/file/<id>`) และแจ้งเฉลยเป็น GitHub Issue (`/report`)
**เพิ่ม: sync ด้วยรหัส**
- Cloudflare KV namespace `MEDLIB_SYNC` (ฟรี)
- `POST /sync/new` → รหัสสุ่ม 12 ตัว (อ่านง่าย เช่น `k7m2-p9qx-4fh8`)
- `GET /sync/<code>` → ไฟล์ความคืบหน้า · `PUT /sync/<code>` → บันทึก (จำกัดขนาด 512 KB, rate limit ต่อ IP)
- เว็บ: หน้าตั้งค่า "ซิงก์ข้ามเครื่อง" สร้างรหัส / ใส่รหัส → ดึงแล้วรวมด้วย `mergeProgress` (มีอยู่แล้ว) → ส่งกลับ · ซิงก์อัตโนมัติเมื่อเปิดเว็บและหลังจบรอบ
- รหัส = กุญแจ ใครรู้รหัสเห็นความคืบหน้า (ไม่มีข้อมูลส่วนตัวอื่น) บอกในหน้าเว็บ
**คู่มือ:** `docs/worker-setup.md` ทีละขั้นสำหรับ kevinzkevier85: สร้าง Worker, ใส่ `DRIVE_API_KEY`, `GITHUB_TOKEN`, `GITHUB_REPO`, `ALLOWED_ORIGINS`, ผูก KV, ใส่ URL ใน `site.json`
**ผลที่ได้หลังตั้ง:** PDF กระโดดไปหน้าของข้อ + ซูม + ออฟไลน์ · แจ้งเฉลยถึงคิว GitHub · ความคืบหน้าตามทุกเครื่อง

## ขั้น 3 — แท็กหัวข้อ
- Claude ร่างรายชื่อหัวข้อต่อบล็อก → **ผู้ใช้ตรวจรายชื่อก่อน** (เช่น END: pituitary, thyroid, adrenal, pancreas/DM, lipid, bone & Ca, อื่น ๆ · CVS ตาม lecture ที่มี)
- ติดแท็กทุกข้อ: END ผ่าน auditor (`repair.json` › `topic` → build) · CVS ใน exam JSON (ไฟล์ไม่มี `generated_by`)
- `lib/validate.js`: `topic` ต้องอยู่ในรายชื่อของบล็อก (`block.json` › `topics`)
- หน้าบล็อก: แท็บ "หัวข้อ" (แทน/คู่กับ Lecture) การ์ดต่อหัวข้อ กดแล้วได้ชุดฝึกข้ามชุด

## ขั้น 4 — หน้าสถิติส่วนตัว (`#/stats`)
- คะแนนรายบล็อก และรายหัวข้อ (ใช้ผลล่าสุดของแต่ละข้อ ไม่นับข้อเฉลยรอยืนยัน) เรียงอ่อนสุดขึ้นก่อน
- กราฟคะแนนของแต่ละรอบตามเวลา (SVG ในหน้า ไม่ใช้ไลบรารีเพิ่ม)
- ปุ่ม "ฝึกหัวข้อที่อ่อนสุด" (สร้างชุดฝึกจากหัวข้อนั้น)

## ขั้น 5 — ทบทวนวันนี้
- ข้อที่ตอบผิด (หรือปักธง) เข้าคิว: กลับมาอีกใน **1 → 3 → 7 วัน** · ตอบถูกครบ 3 ครั้งออกจากคิว · ตอบผิดเริ่มนับใหม่
- เก็บใน progress (`review: { qid: {step, due} }`) จึงซิงก์ไปด้วย · `mergeProgress` รวมโดยเลือก due ที่ใกล้กว่า
- หน้าแรก: กล่อง "ทบทวนวันนี้ X ข้อ" กดแล้วทำต่อเนื่องทุกบล็อก

## ขั้น 6 — ความสะดวก
- หน้าแรก: ปุ่ม "ทำต่อจากล่าสุด" (รอบที่ค้างล่าสุด)
- มือถือ: ปัดซ้าย/ขวาเปลี่ยนข้อ (ไม่ชนกับการเลื่อนแนวตั้ง)
- รูปในข้อ: ใช้นิ้วขยาย/เลื่อน (ต่อยอดจาก `img[data-zoom]`)
