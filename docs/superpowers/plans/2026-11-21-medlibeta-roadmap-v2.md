## A. ผลสอบ & ประวัติ (ข้อ 1 + 7)
**ปัญหาที่ผู้ใช้เจอ:** สรุปผล/ประวัติใช้ยาก ดูยาก · ทำซ้ำได้แค่รอบล่าสุด ย้อนไปทำซ้ำรอบเก่าไม่ได้ · ลบยาก
**โค้ดตอนนี้:** ตารางประวัติเก็บทุกรอบ แต่ปุ่มทำซ้ำซ่อนอยู่ในหน้า "ดูผล" ของแต่ละรอบ · กดเลขข้อในรอบที่จบแล้วเด้งไปหน้าข้อเดี่ยว (ไม่เห็นคำตอบของรอบนั้น) · ลบได้แค่ "ลบประวัติทั้งชุด" · กราฟเป็น %
**ทำ**
- หน้าประวัติเป็น **ไทม์ไลน์การ์ดต่อรอบ** (วันที่ · โหมด · ถูก/ผิด/ไม่ได้ทำ เป็นจำนวนข้อ · เวลา) รอบทำซ้ำซ้อนอยู่ใต้รอบแม่ (`parent` มีอยู่แล้ว)
- ทุกการ์ดมีปุ่ม: **ดูคำตอบรอบนี้** (โหมดอ่านทวน เห็นคำตอบที่เลือก + เฉลย) · **ทำข้อผิดซ้ำ** · **ทำทั้งชุดใหม่** · **ลบรอบนี้** (กดยืนยัน 2 ครั้ง + เลิกทำได้)
- หน้าสรุปผล: หัวเป็นตัวเลขใหญ่ ถูก/ผิด/ไม่ได้ทำ (จำนวน) · ตารางข้อแบบตาราง ✓ ✗ – กดแล้วเปิดคำตอบของรอบนั้น · lecture ที่ควรอ่านอยู่ล่าง
- กราฟพัฒนาการ: แท่งซ้อน จำนวนข้อถูก/ผิดต่อรอบ (แทน %)
**ไฟล์:** `quiz.js` (viewSummary, viewHistory, onClick), `lib/quizcore.js` (ถ้าต้องเพิ่ม helper), `styles.css` · ข้อมูลรอบเดิมใช้ต่อได้ ไม่ต้องย้ายข้อมูล
**ต้องระวัง:** การลบรอบต้องไปถึง sync (`mergeProgress` ต้องรู้ว่ารอบถูกลบ ไม่งั้นเครื่องอื่นจะดึงกลับมา) → ใช้ tombstone

## E. แจ้งปัญหา / Support (ข้อ 3)
**ปัญหา:** ฟอร์มแจ้งเฉลยถามแค่ "ข้อไหนถูก"
**ทำ (ส่วน 1 — ฟอร์ม):** เลือกก่อนว่า **อะไรมีปัญหา**: โจทย์ผิด/ไม่ครบ · ตัวเลือกผิด · เฉลยผิด · คำอธิบายผิด/ไม่ชัด · รูปหาย/ไม่ชัด · อื่น ๆ → แสดงช่องเฉพาะที่เกี่ยว (เลือก "เฉลยผิด" ค่อยถามคำตอบที่คิดว่าถูก) · ส่งผ่าน `/report` เดิม → GitHub issue ติดป้ายตามหมวด
**ทำ (ส่วน 2 — pop-up):** ปุ่มลอยมุมจอ "ติดต่อ/แจ้งปัญหา" ใช้ได้ทุกหน้า (แนบหน้าที่อยู่ + id ข้ออัตโนมัติ) · ดูสถานะเรื่องที่เคยแจ้ง (ดึงจาก issue)
**ยังไม่ทำ:** AI ตอบแชตในเว็บ (ผู้ใช้เปลี่ยนข้อ 6 เป็นเรื่อง workflow ทีม) — พิจารณาภายหลัง
**ไฟล์:** `quiz.js` (reportHTML + handler), `worker/drive-proxy.js` (รับ field `category`), `.github/workflows/claude-issues.yml` (อ่านหมวด)

## C. จัดหมวด ปี → บล็อก (ข้อ 4)
**ผู้ใช้ต้องการ:** ปี → บล็อก → MCQ / KF / OSPE / Lecture · หน้าเว็บแสดงบล็อกเป็นช่อง ๆ (grid) กดแล้ว **pop-up** ออกมาเป็นหน้าบล็อกวิชานั้น
**ทำ**
- หน้าแรก: หัวข้อ "ปี 1 / ปี 2 / ปี 3" แต่ละปีเป็น grid ช่องบล็อก (ใช้ `block.json › year` · ต้องแก้ค่าที่ไม่สม่ำเสมอ: บางบล็อกเป็น `"ปี 2"` บางบล็อกเป็นเลข `3`)
- กดช่อง → แผง pop-up (มือถือเต็มจอ / คอมเป็น modal) มีแท็บ MCQ · KF · OSPE · Lecture → ในแท็บเลือกรุ่น
- เมนูข้างจัดกลุ่มตามปีเหมือนกัน
**ไม่ย้ายไฟล์ข้อมูล** (`data/blocks/<ID>/` เหมือนเดิม) · `lib/validate.js` เพิ่มกติกา `year` เป็นเลข 1–6
**ไฟล์:** `app.js` (viewHome, side, viewBlock), `quiz.js` (examTabHTML), `styles.css`, `block.json` ทุกบล็อก (ฟิลด์ year)

## B. สถิติ & Lecture blueprint (ข้อ 8 + 2)
**ผู้ใช้ต้องการ:** นับเป็นจำนวน ไม่ใช่ % · **จำนวนข้อที่ออกสอบต่อ lecture** · **จำนวนครั้งที่เรื่องนั้นเคยออกสอบ** (ข้ามปี) · ลิงก์ไป lecture
**ทำ**
- หน้า blueprint ต่อบล็อก: ตาราง/heatmap lecture × ปี (52, 51, …) ช่อง = จำนวนข้อที่ออก · รวมต่อแถว = ออกกี่ครั้งทั้งหมด · เรียงมากสุดก่อน
- ข้าง ๆ: ของฉัน ทำแล้ว / ถูก (จำนวนข้อ) · ปุ่ม "อ่าน" (เปิด lecture) และ "ฝึก" (ชุดข้อของ lecture นั้น)
- ระดับหัวข้อ (topic) แบบเดียวกันสำหรับบล็อกที่มี topic
- กราฟในหน้าสถิติเปลี่ยนเป็นจำนวนข้อ
**ติดข้อมูล (ข้อ 2):** blueprint ต้องรู้ว่าแต่ละข้ออยู่ lecture ไหน (`refs[].lecture`) · ตอนนี้มีแค่ END (30 lecture) และ CVS (28) · อีก 18 บล็อก lecture = 0
- ขั้นข้อมูล: หา PDF lecture ใน Drive → ลงทะเบียน `block.json › lectures` → ให้ auditor ติด lecture/topic ต่อข้อ → นำร่องทีละบล็อก
- ระหว่างรอ: blueprint ใช้ระดับ topic หรือแสดง "ยังไม่มีข้อมูล lecture" สำหรับบล็อกนั้น
**ไฟล์:** `quiz.js` (viewStats, หน้าใหม่ `#/blueprint/<block>`), `lib/quizcore.js` (นับ), `auditor/` (ติด lecture)

## D. ระบบเพิ่มข้อสอบใหม่ทั้งราก (ข้อ 5)
**ผู้ใช้ตัดสิน:** ทุกคนเพิ่มได้ → เข้าคิวรอตรวจ → ทีมตรวจแล้วเข้าคลังกลาง
**แนวทาง (ต้องออกแบบละเอียดก่อนทำ)**
1. เว็บ: ฟอร์มใหม่รองรับ MCQ / KF / OSPE + แนบรูป/PDF/ถ่ายรูปข้อสอบ · ตรวจด้วย `lib/validate.js` ก่อนส่ง (กติกาเดียวกับเดิม)
2. ส่งผ่าน Worker → GitHub issue (ป้าย `new-question`) แนบ JSON + ไฟล์ (หรือเก็บไฟล์ใน R2/Drive)
3. ทีม/บอท: แปลงเป็น `auditor/data/work/…` → build → PR → อีกคน merge (ตามกติกา repo)
4. ข้อที่เพิ่มขึ้นป้าย `draft` จนกว่าตรวจ · ผู้เพิ่มเห็นสถานะของตัวเอง
- ฟอร์มเดิม (#/add, เก็บในเครื่อง) เลิกใช้หลังระบบใหม่เสร็จ · ข้อที่คนเคยเพิ่มไว้ในเครื่อง ส่งเข้าคิวได้ด้วยปุ่มเดียว
**ความเสี่ยง:** สแปม/ข้อมูลขยะ → rate limit ใน Worker + ต้องมีรหัสซิงก์ · ขนาดไฟล์แนบ · ข้อสอบมีลิขสิทธิ์/ข้อมูลส่วนตัวในรูป

## F. Workflow ทีม & routing AI (ข้อ 6)
**สถานการณ์:** ตอนนี้ทุกงานใช้ Claude ของ Finn ไม่เลือกโมเดล · อยากส่งงานไปโมเดลฟรี · กังวลประสิทธิภาพตอนสลับโมเดล และ handoff เข้าใจไม่ตรงกัน
**งานที่จะส่งโมเดลฟรี (ผู้ใช้เลือกทั้ง 4):** แยกข้อจาก PDF/อ่านเฉลย · เขียนเฉลยร่างแรก · ตอบ GitHub issue แจ้งเฉลย · ตรวจคุณภาพ/review
**หลักออกแบบ (แก้ปัญหา handoff)**
- **งาน = ไฟล์ task สเปกเดียวกัน** (`auditor/tasks/<id>.json`): input, output schema, คำสั่งตรวจผล (เช่น `node tools/validate.cjs`, `explainQuality`) — โมเดลไหนก็อ่านแบบเดียวกัน ไม่พึ่งความจำของแชต
- **ตัวตัดสินเป็นโค้ด ไม่ใช่โมเดล:** ผลผ่าน `lib/validate.js` + `explain_gate` = รับ · ไม่ผ่าน → ส่งต่อโมเดลที่แรงกว่า (escalate) · Claude ใช้เฉพาะงานที่ตก
- ตาราง routing (`auditor/routing.json`): task → โมเดลลำดับ 1, 2, 3 + เพดานต่อวัน
- บันทึกผลทุกงาน (โมเดล, ผ่าน/ตก, เวลา) เพื่อดูว่าโมเดลฟรีคุ้มจริงไหม
- HANDOFF.md + บรรทัด `ถัดไป:` ใน commit ยังเป็นหลัก แต่เพิ่ม "สถานะ task" อ่านจากไฟล์ task แทน
**ต้องตัดสิน/หาข้อมูลก่อน:** ผู้ให้บริการโมเดลฟรี (เช่น ฟรี tier ของผู้ให้บริการต่าง ๆ / โมเดลรันในเครื่อง) · ข้อจำกัดโควต้า · **ข้อสอบ/เฉลยที่ส่งไปโมเดลฟรีอาจถูกเก็บไปใช้ฝึกโมเดล** ต้องยอมรับได้ · งานอ่านลายมือ/รูปต้องใช้โมเดลที่อ่านภาพได้ · บอท GitHub issue ตอนนี้ผูกกับ Claude Code Action ต้องเปลี่ยน workflow
